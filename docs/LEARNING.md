## 1. Learning 이 하는 일

새 자료를 추천하는 게 아니다.

```
❌ "AWS 공부하려면 이런 유튜브가 있습니다."
✅ "이미 가진 책 3장과 저장해둔 영상 하나면 오늘 45분은 충분합니다."
```

Career OS 의 Learning 은 **선별 시스템**이다.
쌓아둔 것 중에서 지금 필요한 것만 꺼내고, **나머지는 치운다.**

## 3. My Learning Library — Phase 2 에서 만든 것

### 3.1 왜 예전 모델로 안 됐는가

```python
# Phase 2 이전
class LearningResource:
    title
    url = Column(String, nullable=False)   # ← 종이책은 URL 이 없다
    resource_type
    duration_minutes
    importance
    status
    skill_id
```

막고 있는 것:

| 문제 | 설명 |
|---|---|
| `url` 이 필수 | 내가 가진 종이책, 오프라인 강의 자료를 넣을 수 없다 |
| 소유 개념 없음 | "내가 가진 것" 과 "누가 추천한 것" 이 구분되지 않는다 |
| 부분 단위 없음 | "책 3장", "영상 12분 지점부터" 를 가리킬 수 없다 |
| 진행 상태 없음 | `status` 가 `saved`/`completed` 뿐. 어디까지 읽었는지 모른다 |

### 3.2 필요한 개념

```
Library Item          내가 가지고 있거나 저장해둔 것
  ├─ 종류            book · video · course · document · paper · practice · dataset
  ├─ 소유 상태       owned(가짐) · saved(저장함) · wishlist(사고 싶음)
  ├─ 출처            URL 또는 없음(종이책)
  └─ 분량            페이지 수 · 총 길이

Library Segment       그 안의 부분 — 오늘 실제로 소비하는 단위
  ├─ 라벨            "3장 — EC2 기초"
  ├─ 위치            페이지 범위 · 타임스탬프 범위
  ├─ 예상 시간
  └─ 진행 상태       not_started · in_progress · completed
```

**Segment 가 없으면 이 제품의 핵심 문장이 성립하지 않는다.**
"책 한 권을 읽으세요" 가 아니라 "3장을 15분 읽으세요" 여야 한다.

### 3.3 기존 LearningResource 와의 관계

**지우지 않는다.** `LearningResource` 는 Learning Step 에 이미 연결되어 있고
Learning Session 이 그걸 중요도별로 보여준다.

### 결정: 방향 A — `LearningResource` 확장 (Phase 2)

두 방향을 놓고 코드를 본 결과 A 를 골랐다.

```
근거 1   LearningResource 가 이미 10곳에서 쓰인다
         학습 단계 연결 · Session 렌더링 · 우선순위 · 주간 계획 · Agent 도구
         B 를 고르면 그 전부를 이중화하거나 이전해야 한다

근거 2   A 의 우려("라이브러리 항목과 스텝 자료의 성격이 섞인다")는
         실제로는 문제가 아니라 제품 논지 그 자체였다.
         내 라이브러리 항목이 학습 단계에 연결되면 그게 곧 오늘의 자료다.
         둘을 나누면 "내 것 중에서 고른다" 가 오히려 깨진다
```

실제로 바꾼 것:

```
url          NOT NULL → nullable
ownership    owned · saved · wishlist  (기존 행은 saved 로)
total_units / unit_label
Segment      자식 테이블로 추가 (LearningResourceSegment, completed_at 포함)
status       saved · completed 에 서가 값을 더했다 — in_progress · queued · on_hold (8장)
```

> **개념 모델을 그대로 테이블로 옮기지 말 것.**
> 먼저 `backend/app/models.py` 를 읽고 재사용 가능한 것을 찾는다.

## 4. Resource Selector

Library 가 커질수록 중요해지는 부분.

### 입력

```
현재 Learning Step        "EC2 Fundamentals"
연결된 스킬               AWS
오늘 가용 시간            45분
Library 안의 AWS 자료      책 1권(12장) · 영상 5개 · 문서 3개 · 실습 2개
```

### 판단

```
1. Step 과 관련 있는 항목만 남긴다
2. 이미 완료한 Segment 는 제외한다
3. 중요도로 정렬한다        primary → supplementary → deep_dive
4. 가용 시간에 맞게 자른다
5. 나머지는 "지금은 볼 필요 없음" 으로 명시적으로 치운다
```

### 출력

```
이번 세션 자료                              45분 / 예산 45분
이번 세션에는 아래 3개면 충분합니다.

[핵심]  AWS 완벽 가이드 · 3장 — EC2 기초    책 · 가지고 있음 · 오프라인   15분
[핵심]  EC2 인스턴스 직접 띄우기            실습 · 저장해 둠              20분
[보조]  EC2 개요 영상 · 0:00–10:00          영상 · 저장해 둠              10분

▸ 지금 안 해도 되는 자료 4개 — 나머지 자료 4개 → 지금은 볼 필요 없음
    (펼치면 자료마다 이유: "예상 시간이 없습니다" · "오늘 남은 시간(5분)으로는 부족합니다")
```

중요도는 화면에서 `핵심 · 보조 · 깊이 파기` 로 부른다 (`format.js`).
같은 중요도 안에서는 **가진 것 → 저장한 것 → 사고 싶은 것** 순이다
(`library._sort_key`).

**마지막 줄을 빼면 안 된다.**
치운 것을 보여주는 것이 "선별했다" 는 증거다.

단계 하나가 아니라 라이브러리 **전체**에서 고르는 판(`GET /library/selection`)도
있다. 집중 스킬의 다음 단계가 요구하는 자료 → 집중 스킬 자료 순으로 인정하고,
나머지는 치운다. 치운 것은 종류별로 센다 — "63개" 보다 "영상 43개 · 책 11개" 가
부담을 더 덜어준다. 다 본 자료는 치운 것으로 세지 않는다 (`completed_count`).

## 5. Learning Path — 이미 있음

```
AWS 배포 익히기                            33%

✓ Cloud Fundamentals
✓ Region / Availability Zone
● EC2 Fundamentals        ← 현재
○ S3 와 IAM
○ FastAPI 배포
```

- 경로는 스킬에 연결된다. 경로 진행률이 그 스킬의 학습 우선순위에 반영된다
- 단계는 순서를 가진다. 같은 경로에서 `position` 중복은 거부된다
- 단계가 바뀌면 경로 진행률이 즉시 재계산된다

## 6. Learning Session — 이미 있음

```
← 학습

AWS · AWS 배포 익히기 33%                   45분
EC2 Fundamentals  [진행 중]                  예상

왜 지금인가
 · 저장된 공고 2건 중 2건이 AWS 를 요구합니다.
 · 현재 레벨은 0 입니다.
 · 학습 경로 진행률은 33% 입니다.
 [우선순위 1위] [기회 2건 중 2건이 요구] [레벨 0/4]

오늘의 목표                              0 / 3 체크
 □ EC2 가 무엇인지 설명하기
 □ Region 과 Availability Zone 구분하기
 □ EC2 인스턴스 직접 실행하기
 체크는 이 브라우저에만 남아요.           [목표 고치기]

이번 세션 자료                    45분 / 예산 45분
 [핵심]  보유 책 3장                      15분
 [핵심]  EC2 인스턴스 실습                20분
 [보조]  저장한 EC2 영상                  10분
 ▸ 지금 안 해도 되는 자료 N개 — …
 [AWS 자료를 이 단계에 연결 ▾] [연결]

              [ 학습 시작 ]  [ 이 단계 완료로 표시 ]
```

원시 점수(174)는 무엇의 점수인지 말할 수 없어 화면에 올리지 않는다. 대신
분모가 있는 배지를 쓴다. 세션 화면에는 Agent 입력칸을 두지 않는다 — Agent 는
우하단 캡슐(`학습 안내`)이다.

### 근거 규칙

| 구성 | 어디서 오는가 |
|---|---|
| `왜 지금인가` | 저장된 공고 수 · 요구 공고 수 · 현재 레벨 · 프로젝트 증거 · 경로 진행률 |
| `오늘의 목표` | **단계 설명의 각 줄.** 설명에 없는 것은 만들지 않는다. 비어 있으면 `목표 적기` 로 설명을 채운다 |
| `이번 세션 자료` | 연결된 자료를 선별기로 (4장) |

공고가 없으면 "아직 저장된 공고가 없어 시장 수요를 계산할 수 없습니다" 라고
말한다. **수요를 지어내지 않는다.**

### 끝낸 뒤 — 무엇이 바뀌었는지

전에는 끝낸 뒤 "반영되었습니다" 한 줄뿐이라 무엇이 얼마나 바뀌었는지 알 수
없었다. `POST /learning-steps/{id}/complete` 가 전과 후를 함께 돌려준다.

```
✓ 학습 세션 완료
 · 학습 진행률 33% → 67%
 · AWS 의 학습 진행이 우선순위 계산에 반영됩니다
 · 오늘 계획의 'EC2 Fundamentals' 도 완료로 표시했습니다
 [ 다음 단계 보기 · S3 와 IAM ]  [ 오늘 계획으로 ]
```

```
effects         바뀐 것 문장들. 이미 끝낸 단계면 비어 있고, 화면은
                "이미 끝낸 단계라 새로 바뀐 것은 없습니다" 라고 쓴다
next_step       같은 경로의 다음 미완료 단계. 없으면 "이 경로의 마지막 단계였어요"
learning_path   progress_before · progress_percent · completed_steps / total_steps
```

오늘 계획에 같은 단계가 `planned` 로 있으면 함께 끝낸다. 세션에서 끝냈는데
Today 에 할 일로 남아 있으면 두 화면이 다른 말을 한다.

### 아직 없는 것

```
Agent 가 세션 맥락을 이해하는 것       Phase 6
목표 체크 상태를 서버에 저장            목표 자체는 단계 설명(서버), 체크는 브라우저에만
세션 시간 기록 / Start Focus 타이머
```

## 7. Progress

```
not_started → in_progress → completed → (필요하면) review_needed
```

완료가 끝이 아니다.

```
Learning Complete
       ↓
Progress Update          ✅ 구현됨
       ↓
Skill Evidence Update    ✅ evidence_weight 에 반영
       ↓
Priority Recalculation   ✅ 점수가 실제로 내려감
       ↓
Tomorrow Plan            ✅ 집중 스킬이 바뀜
```

### 계산

```
learning_progress = 이 스킬에 연결된 학습 경로들의 평균 진행률
learning_weight   = 1.0 - 0.4 × (learning_progress / 100)
project_weight    = 0.5 (커리어 프로젝트 있음) / 1.0
evidence_weight   = project_weight × learning_weight
```

학습은 프로젝트보다 약한 증거다.
경로를 다 끝내도 가중치는 0.6 까지만 내려가 프로젝트 한 개(0.5)를 넘지 않는다.
"만들어봤다" 가 "배웠다" 보다 강한 증거이기 때문이다.

### 미결

**`Skill.level` 을 학습 완료로 자동 상승시킬 것인가.**

현재는 올리지 않는다. 사용자가 직접 정한 레벨을 시스템이 덮어쓰지 않기 위해서다.
바꾸려면 `services/priority.py` 안에서 처리한다. 새 계산 지점을 만들지 않는다.

## 8. 화면

### 학습 페이지

탭 넷이다 (`LearningPage.jsx`). 사이드바 `내 자료` 는 같은 페이지의 `내 자료`
탭으로 연다.

```
[학습 경로]  [내 자료]  [세션 기록]  [진행과 레벨]
```

`학습 경로` 탭은 경로 목록과, 오른쪽에 다음 단계의 `이번 세션 자료` ·
`왜 지금인가` 를 둔다 (DESIGN.md 8장).

### 내 자료 — 서가

전에는 자료가 세로로 길게 쌓여 있어서 무엇을 보고 있고 무엇이 다음인지
스크롤해야 알았다. 이제 **서가(언제 보는가)마다 가로 레일 하나**다
(`LibraryShelf.jsx`).

```
내 학습 자료                                   [ + 자료 등록 ]
46개 · 챕터 3/8 완료
[ 제목 · 종류 · 스킬 · 학습 경로 · 챕터로 찾기 ]
[전체] [책] [영상] [문서] [실습]

요즘 많이 다룬 자료
 ① AWS 완벽 가이드   최근 30일 · 챕터 2개 끝냄 · 오늘 계획에서 1번 완료

지금 학습 3                                 ‹ ›   전체 보기 →
다음 학습 2
보류 0      보류한 자료가 없습니다.
분류 전 38
[ 완료한 자료 4개 보기 ]

서가 — 언제 보는가.  중요도 — 얼마나 중요한가(상세에서 확인).
```

| 레일 | `shelf` | 비었을 때 |
|---|---|---|
| 지금 학습 | `in_progress` | 안내 + [오늘 계획에서 추천받기] [분류 전 자료 고르기] |
| 다음 학습 | `queued` | "다음에 볼 자료가 없습니다." |
| 보류 | `on_hold` | "보류한 자료가 없습니다." |
| 분류 전 | `saved` | 레일을 숨긴다 |
| 완료 | `completed` | 기본으로 접고 `완료한 자료 N개 보기` 로 연다 |

카드 모양은 자료 종류를 닮는다 — 영상은 썸네일과 재생 시간, 책은 세로 표지,
문서는 종이, 실습은 터미널. 레일 안은 HOT 점수가 높은 것이 앞이다.

#### 서가는 누가 정하는가

**서가와 중요도는 다른 것이다.** 중요도(`primary · supplementary · deep_dive`)는
"얼마나", 서가는 "언제" 다. 둘을 섞지 않는다 (`services/library.py`).

```
사람이 정한 서가가 있으면(status 가 in_progress · queued · on_hold · completed)
  → 그것. 이유 "직접 정한 서가"
없으면 기록으로만 정한다
  챕터를 모두 끝냄                       → 완료        "챕터를 모두 끝내서"
  챕터를 일부 끝냄                       → 지금 학습   "챕터 N개를 끝내서"
  진행 중인 학습 단계에 연결              → 지금 학습   "진행 중인 학습 단계에 연결돼 있어서"
  안 끝낸 학습 단계에 연결                → 다음 학습   "아직 안 끝낸 학습 단계에 연결돼 있어서"
  그 밖                                  → 분류 전     "아직 정하지 않았어요"
```

서가를 옮기는 것은 `POST /resources/{id}/shelf?to=in_progress|queued|on_hold|completed`.
그 밖의 값은 422 다. `분류 전` 으로는 옮길 수 없다 — 사람이 정하지 않은 상태이기
때문이다.

진행률은 **챕터로 셀 수 있을 때만** 준다. 챕터 예상 시간 합으로 가중하고, 시간이
없으면 개수로 센다. 챕터가 없으면 "챕터가 없어 셀 수 없어요" 라고 쓴다.

#### HOT — 요즘 많이 다룬 자료

재미 요소지만 **숫자는 기록에서만 나온다** (`library.build_hot`).

```
기간     최근 30일
센다     완료한 챕터(completed_at) × 2 + 오늘 계획에서 완료한 자료 작업(done) × 1
순위     점수 높은 순 3개. 같으면 자료 id 순
이유     "최근 30일 · 챕터 2개 끝냄 · 오늘 계획에서 1번 완료"
```

기록이 없는 자료는 순위에 넣지 않는다 — **1위를 지어내지 않는다.** 순위가
비면 "최근 30일 동안 챕터를 끝내거나 오늘 계획에서 자료를 완료하면 HOT 순위가
생겨요" 라고 쓴다. `GET /library` 가 `summary · hot · items` 를 한 번에 준다.

#### 자료 하나를 열면 — 오늘 학습에 꺼내기

카드를 누르면 상세 서랍이 열린다: 서가(이유) · 중요도 · 진행률 · 다음 챕터 ·
분량 · 관련 스킬 · 학습 경로 · 보유.

**서가만 바꾸고 끝나면 "꺼냈다" 가 아니다.** `오늘 학습에 꺼내기`
(`POST /resources/{id}/add-to-plan`)는 실제 작업을 오늘 계획에 올린다.

```
제목      "{자료} — {다음 챕터}" (챕터가 없으면 자료 제목)
시간      요청한 분 → 다음 챕터 예상 → 자료 길이 → 30분. 최대 180분
이유      "내 자료에서 직접 꺼냈습니다."
서가      완료가 아니면 지금 학습으로 옮긴다
중복      오늘 같은 자료가 planned 로 있으면 새로 만들지 않고 already_planned
세션      이 자료를 쓰는 안 끝난 학습 단계가 있으면 session_step 을 준다
          → 화면이 "학습 세션 열기" 링크를, 없으면 "오늘 계획 보기" 를 띄운다
```

완료한 자료에서는 버튼이 막힌다. 그 밖의 버튼은 `다음 학습으로 보내기` ·
`지금 학습으로` · `보류로 이동` · `완료로 표시` 다.
