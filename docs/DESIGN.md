## 1. 시각 정체성 — My Career Universe

내 커리어가 하나의 우주다.
중앙의 행성이 **My Career**(현재 커리어 상태), 주변 궤도의 천체가 **영역**이다.

```
                      ● OPPORTUNITIES
                            기회
                        ╭──────────╮
          ● LEARNING                      ● PROJECTS
             학습                            만들기
                 ╲                         ╱
                         Hyun
                      Data / AI
                         50%
              Data / AI 스킬 3개 평균 숙련도
                     집중 · AWS
                 ╱                         ╲
     ● MY LIBRARY                              ● APPLICATIONS
       내가 가진 것                                 지원
                        ╰──────────╯
                      ● EXPERIENCE
                            경험
```

천체는 여섯이다 — `services/universe.py` 의 `PLANETS`. 이름은 영어 대문자,
그 아래 한국어 한 단어(`ko` 의 첫 조각)를 같이 쓴다. Career Agent 는 천체가
아니다 (7장).

링을 좌우로 돌리면 천체가 앞으로 나오고, 그 영역의 상태가 나타난다.
`들어가기 →` 를 누르면 **평범한 작업 화면**으로 들어간다.

궤도 영역의 높이에는 바닥값(`clamp(430px, 56vh, 460px)`)이 있다.
타원 반지름이 `height / 2 - 78` 이라 창이 낮으면 궤도가 쪼그라들어
맨 아래 천체가 중앙 원의 `집중 · …` 줄을 덮는다. 겹치는 것보다
스크롤이 낫다.

### 서사

> Shoot for the moon.
> Even if you miss, you'll land among the stars.

이 문장은 장식이 아니라 **제품 구조와 그대로 맞물린다.**

```
Shoot for the moon            →  Target Career (목표 직무)
Even if you miss              →  못 끝낸 프로젝트, 떨어진 지원
you'll land among the stars   →  Skill Evidence · Experience · Portfolio
```

Career OS 는 실제로 그 변환을 하는 시스템이다. 시도가 증거로 남는다.
그래서 화면의 별도 장식이 아니라 **쌓인 증거의 실제 개수**다 (7장).

## 2. 가장 중요한 원칙

세 개다. 순서대로 중요하다.

### 원칙 1 — 근거 없는 추천은 없다

Career OS 가 무언가를 하라고 하면, **왜 지금 그것인지**가 항상 옆에 붙는다.
설명할 수 없으면 화면에 올리지 않는다.

```
❌  EC2 Fundamentals                      30 min
✅  EC2 Fundamentals                      30 min
    AWS 가 우선순위 1위 — 관심 공고 18건 중 11건이 요구
```

이게 대시보드와 시스템을 가르는 선이다.
대시보드는 숫자를 보여주고 해석을 사용자에게 떠넘긴다.
시스템은 판단을 하고, 그 판단의 근거를 같이 낸다.

> 판단에 쓰인 데이터 전체는 **왜 이 계획인가?** 화면에서 펼쳐 본다 (8장).

### 원칙 2 — 안 해도 되는 것을 말한다

추천 서비스는 계속 뭘 더 보라고 한다. Career OS 는 반대다.

```
지금 필요한 것 · 3개
  📕 Hands-On Machine Learning · 10장          25m
  ▶ AWS EC2 Explained                          18m
  💻 EC2 인스턴스 직접 띄우기                   20m

┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
영상 43개 · 책 11권
지금은 볼 필요 없습니다. 필요해지면 다시 올라옵니다.
```

**치운 것을 보여주는 것까지가 선별이다.** 조용히 감추면 그냥 필터다.
"38개 중 3개만 볼 가치 있음 / 35개는 지금 무시해도 됨" 도 같은 규칙이다.

### 원칙 3 — 홈은 특별하게. 작업 화면은 편하게.

궤도는 **어디로 갈지 정하는 곳**이다.
실제로 학습하고 지원서를 쓰는 화면까지 우주로 만들면
읽기 어려워지고, 차분한 생산성 도구에서 멀어진다.

```
홈 (우주)              어두운 배경 · 궤도 · 은은한 글로우
      ↓ 들어가기
작업 화면 (일반)        밝은 중립 배경 · 카드 · 읽기 쉬운 타이포
```

## 3. 중앙 행성은 장식이 아니다

가운데는 **나**다. 데이터가 아니라 사람이 중심에 있어야 한다.

```
    ╭───────────────╮      ← 테두리를 도는 준비도 링
    │     HYUN      │      ← 이름
    │   Data / AI   │      ← Target Career
    │      50%      │      ← 준비도
    │ Data / AI 스킬 │      ← 무엇의 퍼센트인지
    │  3개 평균 숙련도│
    │  ───────────  │
    │   집중 · AWS   │      ← 지금 집중할 스킬
    ╰───────────────╯
```

이름이 없으면 `MY CAREER`, 목표가 없으면 `목표 미설정`, 집중 스킬이 없으면
`집중 스킬 없음` 으로 둔다 (`Universe.jsx`).

클릭하면 Today Plan 이 열린다.

### 퍼센트는 무엇의 퍼센트인지 같이 쓴다

**"커리어 68% 완료" 는 만들지 않는다.** 커리어에 완료율이란 게 없고,
그런 숫자는 근거를 댈 수 없다.

대신 **목표 직무 스킬의 평균 숙련도**를 쓴다. 레벨 0~4 를 백분율로
바꿔 평균한 값이라 설명할 수 있다. 그리고 퍼센트 바로 아래에
무엇의 퍼센트인지 반드시 같이 쓴다.

목표가 있으면 **그 목표의 스킬만** 센다. 무관한 스킬까지 넣으면
준비도가 실제보다 좋아 보인다.

이름이 가운데 있는 것과 `MY CAREER` 라는 라벨이 있는 것은 다르다.
라벨은 카테고리고, 이름은 사람이다.
화면에서 사용자가 사라지면 그 순간 이건 남의 대시보드가 된다.

### Today 는 왜 행성이 아닌가

Today 는 Learning 이나 Projects 같은 하나의 영역이 아니다.
**모든 영역의 데이터가 Today 로 모인다.**

```
Learning ───────┐
Projects ───────┤
Opportunities ──┤
Experience ─────┤──→  TODAY  ──→  What should I do today?
Applications ───┘
```

그래서 Today 는 중앙 행성에 붙는다. 궤도에 올리면 관계가 뒤집힌다.

### 상태 변화

커리어가 쌓이면 중앙 행성도 아주 미묘하게 변한다.

```
시작            🌑  Starting
학습·프로젝트    🌍  Growing
경험·포트폴리오  🌎  Evidence
지원 시작        🌎  Career System   (위성 추가)
```

**게임의 레벨업처럼 만들지 않는다.**
"내 커리어 시스템이 조금씩 채워지고 있다" 는 정도의 피드백이면 충분하다.

## 4. 영역 = 궤도의 천체

6단계 흐름(DISCOVER → APPLY)은 **데이터가 흐르는 방식**이지 메뉴가 아니다.
사용자가 클릭하는 영역은 이렇게 묶는다.

| 영역 | 들어가는 기능 |
|---|---|
| **Learning** | Learning Path, My Library(책·저장 영상·문서·실습), Learning Session, Progress |
| **Projects** | 프로젝트 진행, Progress, Skill Evidence, 완료 관리 |
| **Opportunities** | 채용공고, 인턴, 공모전, 대외활동, Match, Market Signals |
| **Experience** | Experience Bank, Portfolio, GitHub Evidence, Resume Bullet |
| **Applications** | JD 분석, Experience Matching, 자기소개서, 지원 현황, 면접 |
| **My Library** | 내가 가진 자료 중 오늘 필요한 것 · 치운 것 (학습 화면의 `내 자료` 탭으로 들어간다) |
| **My Career 🌎** | 목표, 현재 상태, 우선순위, Today Plan |

Career Agent 는 궤도에 올리지 않는다. 어느 화면에서든 우하단 캡슐로 붙는다 (7장).

Experience Bank 와 Portfolio 를 별도 최상위로 두지 않는다.
Projects 와 Applications 사이를 잇는 것이므로 Experience 영역 안에 둔다.

---

### 천체는 흩어져 있다

전부 같은 타원 위에 균등 배치하면 **메뉴 바가 휜 것처럼** 보인다.
천체마다 궤도 반경과 크기를 달리 주고, 고리도 셋으로 그린다.

배치값은 **난수가 아니라 고정값**이다. 다시 그릴 때마다 자리가 바뀌면
어디에 무엇이 있는지 외울 수가 없다.

### 배지에는 실제 개수만

```
LEARNING       7개 자료
PROJECTS       1개 진행 중
OPPORTUNITIES  볼 만한 것 2건
EXPERIENCE     ★ 5
APPLICATIONS   3건 진행 중
MY LIBRARY     5개 필요 · 4개 보류
```

홈 배지에는 `New!` `HOT` 같은 말을 쓰지 않는다. **개수를 감추기 때문이다.**
(`내 자료` 화면의 `HOT` 순위는 다르다 — 최근 30일 기록으로만 매기고
이유를 같이 쓴다. LEARNING.md 8장.)

### 오늘 — 궤도 바로 아래, 접히는 선 위

조작 힌트만 있으면 "그래서 뭘 누르지" 가 남는다.

```
        (궤도)

┌ 오늘 ─────────────────────────────────────────────→┐
│ 먼저 · EC2 Fundamentals                             │
│ 학습 · 30분 · 전체 0/3 끝냄                           │
└──────────────────────────────────────────────────────┘
   계획이 없으면  "오늘 뭘 하면 될까요?" · "아직 계획이 없어요 — 눌러서 세우기"
   다 끝냈으면    "오늘 계획을 모두 끝냈어요" · "3개 모두 끝냄"

        (선택한 천체 요약 · 들어가기 →)

┌ 한눈에 보기 ──────────────────────────────────────→┐
│ 지금 상태를 한 장으로                                 │
│ 준비도 · 이번 주 실행 · 영역별 요약                    │
└──────────────────────────────────────────────────────┘
```

**화면에서 채운 요소는 `오늘` 하나다.** 이 앱의 북극성이
"오늘 뭘 하면 되지?" 이므로, 홈을 열었을 때 눈이 먼저 닿는 곳이
거기여야 한다. 개수만 보여서는 답이 안 되므로 **첫 할 일**을 바로 쓴다
(`today.first_task`). `들어가기` 는 테두리만 남긴다 — "지금 보고 있는
천체로 들어간다" 는 부차적 행동이다. 채운 버튼이 둘이면 위계가
없어지고, 열자마자 어디로 갈지가 정해지지 않는다.

`오늘` 을 궤도 **바로 아래**로 올린 이유: 하단에 두었더니
1280×720 노트북에서 접히는 선 아래(644px)로 내려갔다. 북극성이
스크롤 뒤에 있으면 안 된다.

**맨 아래 카드는 `한눈에 보기`(`#/overview`)로 가는 링크다.** 예전
`CAREER AGENT` 안내 카드는 누를 곳이 없는 장식이라 바꿨다 — Agent 는
캡슐이 따로 있다. 이 카드도 채우지 않고 테두리만 둔다(`orbit-card-flat`).

## 4b. 링 인터랙션

Figma 프로토타입의 회전 다이얼 방식을 따른다.
**링에 항목이 붙어 있고, 링을 돌려서 원하는 걸 앞으로 가져온다.**

### 조작

```
드래그          링을 잡고 좌우로 돌린다
← →            한 칸씩 회전
천체 클릭       그 천체를 앞으로 가져온다
놓으면          가장 앞에 온 천체로 스냅
```

### 링이 돌아가는 게 보여야 한다

궤도선만 그려두고 천체만 움직이면 "링이 돈다" 는 느낌이 나지 않는다.
링 자체가 회전한다는 신호가 필요하다.

| 장치 | 규격 |
|---|---|
| **눈금** | 36개. 6개마다 긴 눈금. 천체와 같은 각도로 궤도를 따라 움직인다 |
| **깊이** | 앞(아래)일수록 크고 밝게, 뒤(위)일수록 작고 흐리게 |
| **선택 표식** | 링 아래 **4각 스파클**. "여기가 앞" 을 가리킨다. 로즈 |
| **잡은 상태** | 돌리는 동안 링이 밝아진다 (`brightness(1.45)`) |

### 링 자체

```
굵기        3px (본선) + 12px (바깥 번짐)
그라데이션   위(뒤) #2A3547 55% → 중간 #4A6DA8 → 아래(앞) #7FA6F5 100%
```

**위아래 그라데이션이 깊이를 만든다.** 앞이 밝고 뒤가 어둡다.
링을 균일한 밝기로 그리면 평평해 보이고 3D 감각이 사라진다.

### 선택된 천체

```
점         로즈로 채우고 1.5배 확대
글로우      6px 링 + 13px 옅은 링 + 30px 번짐
이름        연한 로즈, 자간 확대
```

파랑 안에서 "지금 어디" 가 묻히지 않도록 **로즈로 확실하게 분리한다.**

### 선택 표식은 별 모양으로

링 아래 표식을 선이나 삼각형으로 그리면 우주 모티프에서 혼자 떠 보인다.
**4각 스파클**로 그려 별과 같은 언어를 쓴다.

증거의 별과 헷갈리지 않게 색과 모양을 모두 다르게 둔다.

```
선택 표식    로즈 · 4각 스파클 · 22px
증거의 별    앰버 · 원 · 반지름 1.5px
```

### 링 위의 글씨는 반드시 읽혀야 한다

천체 이름이 링 선에 걸치면 읽히지 않는다. 세 가지로 해결한다.

```
① 어두운 후광     text-shadow 로 배경색 글로우를 둘러 링과 분리
② 최소 밝기 보장   뒤쪽 천체도 opacity 0.6 아래로 내리지 않는다
③ 링에서 띄우기    점과 이름 사이 간격을 벌려 글씨가 선을 피한다
```

**뒤쪽이라고 안 보이게 흐리면 안 된다.**
깊이는 크기와 색으로 표현하고, 글씨는 항상 읽을 수 있어야 한다.

### 겹침 금지

중앙 행성과 링이 겹치면 안 된다.

```
중앙 행성 지름   212px  (900px 이하 176px)
링 세로 반경     height / 2 - 78, 상한 148px
궤도 영역 높이   clamp(430px, 56vh, 460px)  (900px 이하 440px)
```

세로 반경의 하한은 반경 식이 아니라 **궤도 영역 높이의 바닥값**이
지킨다 — 높이 430px 이면 반경은 137px 이다. 화면이 좁아져도 이 바닥은
지킨다. 바닥을 두지 않으면 작은 화면에서 링이 중앙 행성을 관통하고
`집중 · AWS` 문구와 겹친다.

## 4c. 별 = 증거

> Even if you miss, you'll land among the stars.

**별의 개수는 실제로 쌓은 증거의 수다.** 예쁘라고 뿌리지 않는다.

### 무엇을 별로 세는가

| 항목 | 근거 |
|---|---|
| 완료한 학습 단계 | 배운 것이 남았다 |
| 완료한 프로젝트 | 만든 것이 남았다 |
| Experience 항목 | 구조화된 경험이 남았다 |
| Portfolio 항목 | 보여줄 수 있는 형태가 됐다 |
| **떨어진 지원** | **인용문 그대로. 못 닿은 시도도 별이 된다** |

### 떨어진 지원을 세는 이유

"Even if you miss" 를 화면에서 지키는 지점이다.
불합격을 숨기면 이 은유가 거짓말이 된다.

다만 **실패를 성취처럼 포장하지 않는다.**
별 하나일 뿐이고, 옆에 무엇으로 이루어졌는지 그대로 적는다.

```
★ 별 6개
  완료한 학습 단계 3 · 완료한 프로젝트 1 · Experience 1
  Portfolio 0 · 떨어진 지원 1
```

### 집계는 어디서 오는가

`GET /analytics/evidence` 하나만 부른다. 화면이 직접 세지 않는다.

```json
{
  "total": 1,
  "is_empty": false,
  "breakdown": [
    { "key": "completed_learning_steps", "label": "완료한 학습 단계", "count": 1 },
    { "key": "completed_projects",       "label": "완료한 프로젝트",   "count": 0 },
    { "key": "experiences",              "label": "Experience",      "count": 0 },
    { "key": "portfolio_entries",        "label": "Portfolio",       "count": 0 },
    { "key": "rejected_applications",    "label": "떨어진 지원",      "count": 0 }
  ]
}
```

**총합만 주지 않는다.** 구성을 함께 주어야 화면이 숫자의 근거를 설명할 수 있다.

판정 기준:

```
완료한 프로젝트   status == "completed" 또는 progress_percent >= 100
                 (진행률만 올리고 상태를 안 바꾼 경우도 센다)
떨어진 지원       status == "rejected"
                 결과가 안 나온 지원은 세지 않는다. 시도가 끝나야 별이다
```

### 규칙

```
✅ 실제 개수만큼만 그린다
✅ 0개면 하늘이 비어 있다. 그게 정확한 상태다
✅ 개수와 구성을 화면에 적는다
❌ 보기 좋으라고 별을 추가하기
❌ 떨어진 지원을 숨기기
❌ 축하 연출 · 파티클 · 레벨업 애니메이션
```

### 표현

```
배경 별      아주 희미한 점 30개. 하늘이 완전히 검지 않게 하는 용도
증거 별      앰버(#E0A458), 반지름 1.5px + 5.5px 옅은 후광
```

증거 별과 배경 별은 명확히 구분되어야 한다.
배경을 증거처럼 보이게 만들면 개수가 거짓이 된다.

## 4d. 천체를 고른 상태 — 들어가기 전 요약

천체를 고르면 **바로 들어가지 않는다.** 궤도 아래 요약 패널이 열린다.

```
LEARNING                학습 · 내 자료
────────────────────────────────────────────────────────────

지금 볼 이유                              다음 학습
  시장 수요   높음  모아둔 기회 2건 중 2건    EC2 Fundamentals  30분
  스킬 격차   높음  레벨 0 · 목표까지 4단계                    [ 들어가기 → ]
  남은 학습   보통  경로 진행률 35%          진행률
                                           AWS 35%
                                         내 자료
                                           5개
```

이 패널이 원칙 1 을 궤도에서 지키는 방법이다.
클릭 → 즉시 이동이면 그냥 메뉴다. 요약을 한 번 거치면 **선택**이 된다.

각 천체가 내놓아야 하는 두 가지 (`services/universe.py`):

| 칸 | 내용 |
|---|---|
| `지금 볼 이유` (`why`) | 이 영역이 지금 중요한 이유 3줄. 세기는 `높음 / 보통 / 낮음`, 옆에 **실제 숫자** |
| 숫자 칸 (`stats`) | 지금 어디까지 와 있는지 · 들어가면 무엇을 하게 되는지. 칸 이름은 천체마다 한국어로 |

| 천체 | 숫자 칸 |
|---|---|
| LEARNING | 다음 학습 · 진행률 · 내 자료 |
| PROJECTS | 진행 중 · 증거 필요 · 증명하는 것 |
| OPPORTUNITIES | 모은 기회 · 가장 잘 맞는 것 · 미뤄도 되는 것 |
| EXPERIENCE | 쌓인 증거 · 정리 대기 · 경험 창고 |
| APPLICATIONS | 진행 중 · 가장 가까운 마감 · 자기소개서 |
| MY LIBRARY | 가진 자료 · 지금 필요 · 챕터 |

**Opportunities 와 My Library 는 여기서 원칙 2 도 지킨다.**

```
OPPORTUNITIES                          MY LIBRARY
  모은 기회        38건                   가진 자료   12개
                   볼 가치 3건                        저장 34개
  가장 잘 맞는 것  AI 데이터 분석 공모전   지금 필요   3개
                   91%                                나머지 63개는 지금 아님
  미뤄도 되는 것   35건                   챕터        3 / 8
                   지금은 무시해도 됩니다              조각 완료
```

## 5. 우주지, 우주 게임이 아니다

### 하지 않는 것

```
❌ 네온 글로우 남발
❌ 별 수천 개
❌ 자동으로 계속 도는 카메라
❌ SF 폰트
❌ HUD 숫자 잔뜩
❌ 행성이 빠르게 움직이기
```

### 하는 것

```
✅ 파랑으로 살짝 기운 근사 블랙 배경
✅ 궤도선 하나. 그라데이션으로 앞뒤 깊이를 준다
✅ 아주 은은한 파란 글로우
✅ 별은 증거 개수만큼만. 배경 별은 극히 희미하게
✅ 사용자가 돌릴 때만 회전
✅ 강조색 셋을 역할대로만 쓴다 (아래 표)
```

### 색

```
--void        #070A10    배경 (파랑으로 기운 근사 블랙)
--surface     #141C29    패널
--line        #232E3E    경계선
--text        #E8EDF5
--muted       #7E8CA2
--good        #4FB286    상태 표시
```

강조색은 **셋. 각각 역할이 다르고 섞어 쓰지 않는다.**

| 토큰 | 값 | 역할 | 쓰는 곳 |
|---|---|---|---|
| `--accent` | `#5B8DEF` | 시스템 · 궤도 · 진입 | 링, 중앙 행성 테두리, `들어가기` 버튼 |
| `--select` | `#F0709F` | **지금 고른 것** | 앞으로 나온 천체, 선택 표식, 패널 제목 |
| `--now` | `#E0A458` | **내 커리어의 실체** | 오늘의 집중(FOCUS), 증거의 별 |

로즈를 넣은 이유는 "어디를 고르고 있는지" 가 파랑 안에서 묻혔기 때문이다.
파랑은 배경 시스템이고, 로즈는 **사용자의 현재 위치**다.
앰버는 내가 실제로 쌓은 것 — 오늘 할 일과 별.

세 색이 겹치는 곳이 없어야 한다. 겹치면 의미가 사라진다.

작업 화면의 테두리와 바닥에는 **남색을 아주 조금 섞는다.**
중립 회색이면 우주에서 내려온 화면 같지가 않고, 세게 넣으면 카드가
파래져서 읽기가 나빠진다. 홈의 `--deep` 을 흰색에 극소량 탄 값이다.

```
--paper       #F3F5FA    바닥      (중립 #F5F6F8 에서)
--card        #FFFFFF    카드      (그대로 — 읽기가 먼저다)
--line        #DCE1EC    테두리    (중립 #E6E7EB 에서)
--line-soft   #E8EBF3    구분선    (중립 #EEEFF2 에서)
--ink         #17181C
--ink-soft    #777B85
--ink-faint   #A6A9B2
```

강조색 셋은 **작업 화면에서도 같은 값**을 쓴다. 어긋나면 내려오는
순간 다른 앱에 들어온 것처럼 읽힌다.

| | 홈에서 | 작업 화면에서 |
|---|---|---|
| `--accent` `#5B8DEF` | 링 · 중앙 테두리 · 들어가기 | 목표 직무 · 활성 네비 · 링크 |
| `--select` `#F0709F` | 앞으로 나온 천체 | 지금 고른 탭 · 선택된 목록 행 |
| `--evidence` `#E0A458` | 증거의 별 | ★ 증거 · Agent 캡슐의 ✦ |

### 작업 화면의 공통 컴포넌트 — `ui.jsx` · `ui.css`

화면마다 로딩 문구 · 오류 · 빈 상태를 따로 만들다 보니 어떤 화면은 다시
시도할 길이 없었다. 그래서 작업 화면은 `frontend/src/components/ui.jsx` 의
공통 컴포넌트를 쓴다.

```
Button          primary · secondary · quiet · danger. writes 면 읽기 전용 데모에서 막힌다
LoadingState    "불러오는 중…"
ErrorState      오류 문장 + [다시 불러오기]
EmptyState      안내문으로 끝내지 않고 다음에 누를 것을 같이 준다
NextActionCard  현재 상태 → 다음에 할 일 → 버튼. 화면마다 맨 위에 하나 (기본 eyebrow "다음 행동")
WhyPanel        결론 문장이 먼저, 숫자는 [근거 숫자 보기] 뒤로 접는다 ("왜 이 계획인가?")
ConfirmButton   되돌리기 어려운 일은 두 번 누른다 ("정말 할까요?")
ProgressBar · StatusBadge · Notice
```

`ui.css` 는 `App.css :root` 의 바닥 · 선 토큰을 그대로 두고 **의미 있는 색만**
더한다.

```
--action  #3B67C4   행동 · 진행 중
--warn    #9A5A00   마감 · 주의
--ok      #2B7348   완료 · 보유
--bad     #B3261E   부족 · 초과 · 오류
```

(각각 `-soft` 바탕색이 짝으로 있다. 강조색 셋과 섞어 쓰지 않는다.)

### 타이포

```
IBM Plex Sans / IBM Plex Sans KR    본문·제목
IBM Plex Mono                        라벨 · 숫자 · 궤도 데이터
```

"OS" 라는 성격에 맞고, 한글 지원이 있으며, 흔한 기본값이 아니다.

## 6. 구현 방식 — CSS + SVG

**결정: 3D 라이브러리 없이 만든다.**

한 번 Three.js 로 가기로 했다가 되돌렸다. 이유는 다음과 같다.

```
현재 프런트 런타임 의존성은 react / react-dom 둘뿐이다
시안(SVG + CSS)이 이미 필요한 인터랙션을 전부 보여준다
  — 링 회전 · 눈금 · 스냅 · 깊이 표현 · 선택 강조
접근성을 처음부터 DOM 으로 가져갈 수 있다
저사양 기기와 모바일에서 가볍다
```

진짜 원근감과 카메라 이동이 필요해지면 그때 다시 판단한다.
**지금 필요한 것은 "링을 돌려 영역을 고른다" 이고, 그건 CSS 로 된다.**

### 그래도 지킬 것

```
1. 키보드로 완전히 조작 가능해야 한다
   ← → 로 궤도 회전, Enter 로 진입, Tab 으로 순회

2. 천체는 실제 버튼이어야 한다
   캔버스에 그림만 그리면 화면 낭독기가 읽지 못한다

3. prefers-reduced-motion 을 존중한다
   회전 애니메이션을 끄고 즉시 전환한다

4. 홈에서만 쓴다
   작업 화면에는 궤도 관련 코드를 로드하지 않는다

5. 별 개수는 데이터가 정한다
   보기 좋으라고 늘리지 않는다 (4c 참고)

6. 좁은 화면에서는 궤도를 포기한다
   768px 미만에서는 세로 목록으로 바꾼다.
   작은 화면에서 궤도를 억지로 돌리게 하지 않는다
```

### 구현 메모

시안이 그대로 기준 구현이다.

```
궤도        SVG ellipse + 세로 그라데이션 (앞이 밝고 뒤가 어둡다)
천체        절대 위치 button, 각도로 좌표 계산, 깊이에 따라 scale/opacity
눈금        36개. 천체와 같은 각도로 움직여 링이 도는 것을 보여준다
회전        rAF 로 target 각도까지 보간, 놓으면 가장 앞으로 스냅
별          canvas. 증거 개수만큼만 그린다
```

## 7. 진입 후 — 작업 화면

`들어가기` 이후에는 좌측 사이드바 구조로 바뀐다.

```
┌──────────────┬────────────────────────────────────────┐
│ ◉ Career OS  │  (도착 띠 — 우주 바닥색이 종이색에 녹는다) │
│              │   CAREER OS                            │
│  ▦ 한눈에 보기 │   좋은 아침이에요, Hyun.                │
│  ◎ 오늘       │   Data / AI · 지금은 AWS                │
│  ◷ 캘린더     │   이번 주 40분 · 완료 1개 · 1일          │
│  ◈ 학습       ├────────────────────────────────────────┤
│  ▲ 프로젝트   │  (작업 화면 — 밝은 종이색)              │
│  ◇ 기회       │                                        │
│  ▤ 내 자료    │                                        │
│  ✉ 지원서     │   ┌──────────────────────────────┐     │
│  ★ 경험       │   │ ✦ 오늘 계획 안내   물어보기    │     │
│  ◑ 회고       │   └──────────────────────────────┘     │
│              │                                        │
│  ← 우주 홈    │                                        │
└──────────────┴────────────────────────────────────────┘
```

**작업 화면의 이름은 한국어다** (2026-09-15 결정, `Sidebar.jsx`). 영어를
함께 쓰는 곳은 홈의 천체 이름뿐이다.

**사이드바는 우주 바닥색이다.** 본문만 종이색이면 왼쪽에 계속 우주가
붙어 있는 셈이라 홈과 이어진다. 상단 탭이 아닌 이유는 단순하다 —
항목이 늘면서(지금 10개) 가로로 밀렸다.

### 도착 띠

`들어가기` 를 누르면 우주에서 뚝 떨어져 흰 화면이 나왔다. 같은 앱 같지
않았다. 그렇다고 작업 화면을 어둡게 만들 수는 없다 — 읽기가 나빠지고
원칙 3 을 깬다.

상단에 우주 바닥색 띠를 깔고 **아래로 종이색에 녹인다.** 경계선을
두면 그냥 검은 막대가 되므로 그라데이션으로 지운다. 홈의 증거 별도
네 개만 데려온다 — 많으면 조잡해진다.

사이드바 맨 아래 `← 우주 홈` 으로 언제든 홈으로 돌아간다.

### 한눈에 보기(Overview)는 Today 에서 밀려난 것들의 자리다

Today 는 "나와 오늘" 둘만 있어야 한다. 그런데 주간 계획·학습
우선순위 표·공고 원본 목록은 지울 수 없는 것들이다.
**지우지 않고 `한눈에 보기` 로 옮긴다** — 다만 매일 아침 볼 것은 아니다.
홈 맨 아래 카드가 여기로 온다.

### Projects 와 Experience 는 다른 화면이다

프로젝트는 **만드는 동안**이 길고, 그 동안 볼 화면이 필요하다.
끝난 뒤에 증거가 되는 것은 Experience 의 일이다.
두 천체가 완전히 같은 곳으로 가면 둘 중 하나는 거짓말이다.

### Career Agent 는 중심이 아니라 동반자다

화면 맨 위의 커다란 입력창은 **ChatGPT 껍데기처럼 보인다.**
Career OS 의 가치는 대화창이 아니라 판단에 있다.
그래서 Agent 는 사이드바 항목도, 상단 고정 입력창도 아니고
화면 우하단의 작은 캡슐이다.

그리고 **어느 화면이냐에 따라 역할이 바뀐다.**

| 화면 | 역할 | 하는 일 (캡슐 아래 한 줄) |
|---|---|---|
| 오늘 · 왜 이 계획인가? | 오늘 계획 안내 | 오늘 계획 · 우선순위 · 진행 상황을 찾아 보여줘요 |
| 한눈에 보기 | 상태 안내 | 오늘 할 일 · 프로젝트 진행률을 찾아 보여줘요 |
| 캘린더 | 시간 안내 | 오늘 쓸 수 있는 시간으로 계획을 보여줘요 |
| 학습 · 내 자료 | 학습 안내 | 다음 학습 단계 · 우선순위를 찾아 보여줘요 |
| 프로젝트 | 프로젝트 안내 | 진행 중인 것 · 남은 것을 찾아 보여줘요 |
| 기회 | 기회 안내 | 저장된 공고를 찾아 보여줘요 |
| 경험 | 경험 안내 | 프로젝트 진행과 오늘 할 일을 찾아 보여줘요 |
| 지원서 | 지원서 안내 | 저장된 공고를 찾아 보여줘요 |
| 회고 | 회고 안내 | 프로젝트 진행률 · 오늘 할 일을 찾아 보여줘요 |

역할 이름을 캡슐에 그대로 띄운다(`CareerCompanion.jsx` 의 `ROLES`) —
지금 무엇을 물어볼 수 있는지가 보여야 한다. 열면 화면별 예시 질문 버튼이
같이 뜬다.

### 이름은 실제로 할 수 있는 일에 맞춘다

전에는 `Learning Tutor` 라고 부르면서 옆에 "개념 설명은 못 합니다" 를
같이 적었다. 정직하긴 한데 **이름이 기능을 과장한다.**
사용자 입장에서는 "그러면 튜터가 아닌데?" 가 자연스러운 반응이다.

```
❌  Learning Tutor
    ⚠ 학습 개념을 설명할 수 없습니다

✅  학습 안내
    다음 학습 단계 · 우선순위를 찾아 보여줘요
```

지금 이 Agent 가 하는 일은 **안내**다 — LLM 없이 키워드로 의도를 갈라
저장된 것 중에서 찾아주고 다음에 뭘 할지 가리킨다. 그래서 `안내` 다.
(영어 `Guide` 이름을 쓰다가 작업 화면을 한국어로 바꾸면서 옮겼다.)

개념을 설명하고 이해 여부를 확인할 수 있게 되면 그때 튜터로
올린다. **못 하는 것을 나열하는 대신 이름을 낮추는 쪽이
제품 신뢰도를 높인다.**

### 정보 위계 3단계

```
1차   지금 해야 할 것       가장 크고, 가장 위
2차   현재 상태             중간
3차   참고 데이터           작게, 아래 또는 하위 페이지
```

### 컴포넌트 원칙

1. **카드는 의미 단위다.** 시각 효과를 위해 카드를 만들지 않는다
2. **빈 상태를 설계한다.** "데이터 없음" 이 아니라 다음 행동을 안내한다
   ```
   ❌ No projects yet.
   ✅ 아직 프로젝트가 없습니다.
      AWS 학습을 마치면 배포 프로젝트를 시작하는 걸 권합니다.
      [ 프로젝트 만들기 ]
   ```
3. **숫자에는 맥락을 붙인다.** `200` 이 아니라 `우선순위 200 · 시장 수요 100%`
4. **오류는 국소화한다.** Agent 가 실패해도 나머지 화면은 살아있어야 한다
   (현재 구현이 이미 이렇게 되어 있다)

## 8. 화면 와이어프레임

### Today (중앙 행성 진입)

홈에서 들어오면 **두 가지만** 있다. 나, 그리고 오늘.
카드 15개를 늘어놓지 않는다.

이름과 이번 주 누적은 **도착 띠**가 맡는다 (7장). 본문은 요약 카드
하나로 오늘의 상태와 가장 먼저 할 일을 말하고, 계획과 그 근거를 나란히
둔다 (`TodayPage.jsx`).

```
좋은 아침이에요  9월 15일 (월)
┌ 오늘 사용할 수 있는 시간 ┐ ┌ 오늘의 핵심 초점 ─────┐ ┌ 오늘 진행 ┐
│ 2시간                    │ │ AWS                    │ │ 0 / 3     │
│ 일정을 빼고 빈 … 중 …    │ │ 시장 수요 2건 · 레벨 0 │ │ ━━━━━━━━ │
└──────────────────────────┘ └────────────────────────┘ └───────────┘
┌ ▶ 가장 먼저 할 일 ────────────────────────────────────────────────┐
│ EC2 Fundamentals                                     [ 시작하기 ] │
│ 학습 · 30분                                                        │
│ AWS 가 우선순위 1위 — 모아둔 기회 2건 중 2건이 요구                │

오늘 할 일                [시간 · 강도 설정] │ 왜 이 계획인가?
계획 2시간 · 강도 보통                        │ (결론 한 문장)
 1  [학습] EC2 Fundamentals            30분  │ ▸ 근거 숫자 보기
    선택 이유  AWS 가 우선순위 1위 — …        │     시장 수요  AWS · 2 / 2
    완료하면   …                              │     내 수준    레벨 0 · …
    [시작] [오늘은 넘기기]                    │     학습       …
 2  [프로젝트] AWS Deployment          60분  │     오늘 시간  120분
 3  …                                         │
 ▸ 나머지 N개 더 보기                         │ 계산 근거 전체 보기 →
                                              │ 쓰인 데이터 8 / 8종
```

**계획이 먼저, 근거가 그다음.** 아래에 `집중 스킬` 카드(`TodayFocus`)가
와서 "왜 지금 이 스킬인가" 를 시장 수요 · 내 수준 · 학습 진행 · 프로젝트
증거로 편다. 근거를 위에 두면 답이 접히는 선 아래로 내려간다 — 홈에서
`오늘` 을 올린 것과 같은 이유다.

**맨 위는 숫자 셋과 할 일 하나다.** 쓸 수 있는 시간 · 핵심 초점 ·
진행을 한 줄로 두고, 그 아래 `가장 먼저 할 일` 카드(`NextActionCard`)의
`시작하기` 가 첫 항목이 있는 실제 화면으로 데려간다. 아무 데도 데려가지
않으면 버튼이 아니라 장식이다.

**`사용 가능 시간` · `강도` 는 접어둔다.** 매일 설정부터 만지게 만들면
그건 도구가 아니라 폼이다. 계획을 먼저 보여주고 조절은
`시간 · 강도 설정` 뒤로.

**크게 보여주는 항목은 셋이다.** 나머지는 지우지 않고 `나머지 N개 더 보기`
로 접는다.

우측 근거 칸은 결정에 직접 쓰인 네 입력(시장 수요 · 내 수준 · 학습 ·
오늘 시간)만, 그중 데이터가 있는 것만 보여준다. 여덟 개를 다 올리면 계산
설명 화면이 된다. 전체와 못 쓴 입력은 `왜 이 계획인가?` 화면에서 펼친다.

**항목마다 `선택 이유` 줄이 반드시 있다.** 그게 원칙 1 이다.
이유를 못 쓰겠으면 그 항목은 계획에 넣지 않는다.

### 왜 이 계획인가? (Why this plan?)

원칙 1 을 전면에 세우는 화면. "얘가 아무 말이나 하는 게 아니구나" 가
생기는 자리다.

**격자에 값만 늘어놓으면 "그래서 이게 왜?" 가 남는다.**
한 줄에 한 문장씩 두고, 펼치면 그 문장이 나온 원본 숫자를 보여준다.

```
← 오늘 계획

왜 이 계획인가?
(서비스가 만든 결론 한 문장)
2026-09-07 · 집중 스킬 AWS · 쓰인 데이터 8 / 8종

판단에 쓴 것 · 눌러서 원본 숫자 보기
 ◎  목표 직무   Data / AI                                    ›
               목표 직무가 모든 판단의 기준점입니다.
 ▤  시장 수요   AWS · 1 / 1                                  ⌃
               …
                │ (계산에 들어간 원본 숫자 줄들)
 △  내 수준     레벨 0 · 목표까지 4단계                        ›
 ▲  프로젝트    100%                                         ›
 ◈  학습        FastAPI 배포                                  ›
 ▣  내 자료     관련 자료 7개                                 ›
 ◷  마감        임박한 것 없음                                ›
 ◔  오늘 시간   120분                                        ›

┌ 그래서 고른 것 ──────────────────────────────────────┐
│   프로젝트 · AWS Deployment                      45분 │
│   지원     · 지원 준비 — AI 데이터 분석 공모전    30분 │
│   학습     · FastAPI 배포                        45분 │
│   ────────────────────────────────────────────────── │
│   합계 120분 / 120분          이 판단에 쓰인 데이터 8종 │
└──────────────────────────────────────────────────────┘

이 판단의 한계
  · (서비스가 준 한계 문장들)
```

입력은 여덟 종이다 — `services/why.py` 의 `target · market · gap · project ·
learning · library · deadline · time`. 칸 이름은 `KOREAN` 표의 한국어를
쓰고, 서비스 안의 영어 라벨(`MARKET` 등)은 화면에 내보내지 않는다.

**펼쳐서 보여줄 게 없으면 화살표는 장식이다.** 그래서 각 칸은 계산에
들어간 값과, 그 값이 점수에 어떻게 쓰이는지까지 갖는다.

```
내 수준     현재 레벨 0 / 목표 레벨 4 / 격차 4단계
            격차가 0 이면 우선순위도 0 이 됩니다
프로젝트    커리어 프로젝트가 있으면 증거 가중치가 0.5 로 낮아집니다
            이미 증명 중인 스킬은 덜 급하기 때문입니다
```

**"없음" 도 판단이다.** `마감` 이 비어 있어도 무엇을 보고 없다고
했는지 적는다 — 기한 14일 안에 든 마감 0건, 지원서와 기회를 함께 봤다.

데이터가 없어 못 쓴 입력은 **칸을 지우지 않고** 흐리게 남긴다.
칸이 사라지면 무엇을 못 봤는지 알 수 없고, 그러면 근거가 아니라
편집된 요약이다.

### Learning

탭 넷. **왼쪽은 어디까지 왔는지, 오른쪽은 지금 할 것 하나.**
목록만 있으면 "그래서 뭐부터?" 가 남는다.

```

┌ ▶ AWS 배포 익히기 · 2/3단계 완료 · 67% ───────────────────────┐
│ FastAPI 배포                                   [ 세션 시작하기 ] │

└─────────────────────────────────────────────────────────────────┘

AWS 배포 익히기              67%      │ 이번 세션 자료
진행 중 · 2/3 단계                    │  AWS 완벽 가이드 · 5장   [핵심]
━━━━━━━━━━━━━━━━━━━━━━                │  가지고 있음 · 20분
 ✓  EC2 Fundamentals    완료  100%    │  AWS 아키텍처 백서       [깊이 파기]
 ✓  S3 와 IAM           완료  100%    │  지금 안 해도 되는 자료 2개
 03 FastAPI 배포      시작 전   0%    │
                                      │ 왜 지금인가
                                      │  · 공고 1건 중 1건이 AWS 요구
                                      │  · 현재 레벨은 0 입니다
                                      │ 핵심 — 이번 단계에 꼭 볼 것 · …
```

오른쪽 패널은 **다음 단계의 세션 데이터를 그대로 쓴다.** 여기서 자료를
다시 고르면 세션 화면과 다른 것을 권하게 된다.

중요도는 `핵심 / 보조 / 깊이 파기` 로 부르고 색으로 구분한다
(`format.js`). 셋을 같은 색으로 두면 선별했다는 사실이 화면에서 사라진다.

| 탭 | 하는 일 |
|---|---|
| 학습 경로 | 지금 어디까지 왔고 다음이 무엇인지 |
| 내 자료 | 가진 것을 서가로 정리하고 오늘 꺼내기 (아래 참고) |
| 세션 기록 | 진행 중이거나 끝낸 단계. 아직 시작 안 한 것은 없다 |
| 진행과 레벨 | 경로별 진행률 · 스킬 레벨. 퍼센트에 분모를 같이 쓴다 |

### 닫힌 것

| 화면 요소 | 어떻게 |
|---|---|

| 주간 누적 시간 | `DailyPlanTask` 완료분 합계 (새 기록 없이) |

### 그 과정에서 고친 것

| 문제 | 고친 방식 |
|---|---|
| 분모 없는 퍼센트 | `100%` → `등록 공고 1건 중 1건`. 서비스가 분모를 같이 낸다 |
| 엔터한 곳 ≠ 도착한 곳 | 천체에 `route` 뿐 아니라 `section` 을 붙였다 |
| 두 천체가 같은 목적지 | 테스트로 막았다. 같은 곳이면 하나는 거짓말이다 |
| `ProjectResponse` 에 skills 누락 | 응답 필드 누락은 이 저장소에서 네 번째. 테스트로 막았다 |
| 스킬 0개일 때 홈이 500 | `_learning` 조기 반환이 배지를 빼먹었다 |
| 조회가 조용히 쓰기 | 홈에서 `score_all` 을 부르지 않고 저장된 점수만 읽는다 |

## 오늘 계획의 규칙 — 이월의 수명

후보 순서는 **마감 → 이월 → 학습 → 프로젝트** 이고, 강도가 정한
`max_tasks` 만큼만 들어간다(보통 3개).

**이월은 3일까지만 산다.** 넘기면 후보에서 빠지고 Today 화면 위쪽에
`이건 안 할 건가요?` 로 올라온다.

```
┌ 이건 안 할 건가요?   사흘 넘게 미뤄서 오늘 계획에서 뺐습니다 ┐
│ AWS Deployment Project      4일째   [그래도 할래요] [치우기] │
└──────────────────────────────────────────────────────────┘
```

이월이 무한하면 하루 세 칸을 옛 계획이 다 차지하고, 그 사이 우선순위가
바뀌어도 1위가 영영 못 들어온다. 실제로 났다 (DECISIONS.md 19장).

**두 답이 다 가능해야 한다.** `그래도 할래요` 는 나이를 오늘로 되돌려
다시 후보로 만들고, `치우기` 는 skip 한다. 치우는 길만 있으면 그건
묻는 게 아니라 버리는 것이다.

같은 대상을 두 번 올리지 않는다 — 이월과 신규 후보가 같은 프로젝트를
가리킬 수 있다.

있었고, 경험·포트폴리오·공고·지원에도 시각이 있다. 매일 기록은
되고 있었는데 모아서 보여주는 곳만 없었다.

**세지 못하는 것은 세지 않는다.** `projects` 에는 시각이 없어서
"이번 달에 프로젝트를 끝냈다" 는 아직 계산할 수 없다. 화면 아래에 그
사실을 적는다 — 숨기면 회고 전체가 못 믿을 것이 된다.

**스킬 레벨은 이력으로 센다.** `skill_level_events` 가 변화를 남기고,
회고는 한 달치를 처음과 끝으로 접어 보여준다 — `0 → 1 → 2` 는 두 번
오른 것이 아니라 "0에서 2로" 한 줄이다. 제자리로 돌아온 것
(`0 → 1 → 0`)은 변화가 아니다.

**비어 있으면 비어 있다고 한다.** "이 달에는 기록된 것이 없습니다.
비어 있다는 것도 정확한 상태입니다."
