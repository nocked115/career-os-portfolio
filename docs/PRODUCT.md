## 1. 왜 만들려고 했는가

출발점은 취업 관리 앱이 아니었다.

문제는 이거였다.

> 공부할 책도 많고, 저장해둔 강의와 자료도 많고,
> 하고 싶은 프로젝트도 많고, 취업 준비도 해야 하는데
> **결국 지금 뭘 해야 하는지 몰라서 실행이 안 되는 문제.**

정보가 없어서가 아니다. 정보는 넘친다.
문제는 그것들이 **연결되어 있지 않다**는 것이다.

```
채용공고는 북마크만 쌓임      → 어떤 역량이 부족한지 모름
강의는 결제만 하고 안 봄       → 왜 지금 그걸 들어야 하는지 모름
책은 사두고 안 폄              → 어느 챕터가 지금 필요한지 모름
프로젝트는 했는데 기억 안 남   → 자소서 쓸 때마다 처음부터 떠올림
"열심히" 하는데 방향을 모름    → 오늘 한 일이 뭐에 기여했는지 추적 안 됨
```

본질은 **의사결정 비용**이다.
무엇을 할지 정하는 데 에너지를 다 쓰고, 정작 실행할 힘이 남지 않는다.

그래서 Career OS 가 해야 하는 가장 중요한 일은 하나다.

> **내 목표와 현재 상태를 보고, 지금 가장 가치 있는 다음 행동을 결정해주는 것.**

Career OS 는 정보를 더 쌓는 서비스가 아니라
**쌓여 있는 것들을 실행으로 바꾸는 시스템**이다.

---

## 2. 한 문장 정의

> Career OS 는 취업 시장, 나의 역량, 가지고 있는 학습 자료, 프로젝트와 경험,
> 지원 현황을 연결해 **지금 무엇을 해야 하는지를 결정해주는**
> 개인 Career Operating System 이다.

## 3. 북극성

제품이 계속 대답해야 하는 질문은 하나다.

```
What should I work on today?
```

이게 프로젝트의 북극성이다.

### 기능 추가 필터

새 아이디어가 나왔다고 바로 기능 목록에 넣지 않는다.
반드시 이 필터를 거친다.

```
이 기능은
DISCOVER / DECIDE / LEARN / BUILD / PROVE / APPLY
중 어디에 속하는가?
            ↓
Today's Action 을 더 잘 결정하게 만드는가?
            ↓
      YES → 검토
      NO  → Backlog
```

이 필터가 없으면 제품은 또 산으로 간다.
실제로 한 번 그랬다 — 세션마다 좋은 기능이 하나씩 붙으면서
"이 앱을 켜면 나는 무엇을 하게 되는가" 가 흐려졌다.

## 5. My Learning Library — 이 제품의 성격을 결정하는 부분

Career OS 가 해야 할 말은 이게 아니다.

```
❌ "AWS 공부하려면 이런 유튜브가 있습니다."
```

이거다.

```
✅ "이미 저장해둔 영상과 가지고 있는 책이 이만큼인데, 지금 뭘 봐야 하지?"
```

그래서 Learning 의 핵심은 추천 엔진이 아니라 **내 것 중에서 고르는 것**이다.

```
내 자료

📕 내 책             내가 실제로 가진 책 (챕터 단위)
▶  저장한 영상        저장해둔 YouTube · 강의
📄 문서              공식 문서 · 논문 · 아티클
💻 실습              코딩 문제 · 데이터셋 · 실습
```

### 판단 과정

```
목표 직무 (Data / AI)
        ↓
최근 관심 공고 분석
        ↓
AWS 필요 ↑
        ↓
현재 AWS Skill Evidence 부족
        ↓
Learning Priority: AWS = HIGH
        ↓
현재 Learning Step: EC2 Fundamentals
        ↓
내 Library 검색
        ↓
오늘 필요한 것만 선택
```

### 결과

```
오늘 · AWS EC2                        45분

핵심
📕 보유 책 3장                          15분
💻 EC2 인스턴스 실행                    20분

보조
▶ 저장한 EC2 영상                       10분

──────────────────────────────────────────
나머지 AWS 영상 4개
→ 지금은 볼 필요 없음
```

**마지막 문장이 핵심이다.**

Career OS 는 추천 시스템이면서 동시에
**안 해도 되는 것을 제거해주는 시스템**이어야 한다.

## 6. Today 가 제품의 중심

기능이 아무리 많아져도 사용자가 가장 자주 보는 화면은 Today 다.
내부에서 아무리 복잡한 계산을 하더라도, 사용자가 보는 건 이만큼이면 된다.

```
오늘 쓸 수 있는 시간   2시간
핵심 초점             AWS
가장 먼저 할 일        EC2 기초 — 30분        [ 시작 ]

──────────────────────────

오늘 할 일

□ EC2 기초                  30분   학습
□ AWS 배포 프로젝트          60분   프로젝트
□ 지원 공고에 쓸 경험 정리    30분   지원서

──────────────────────────

합계                       120분
```

작업 화면의 이름과 라벨은 한국어다. 영어는 홈의 행성 이름(`LEARNING · 학습 · 내 자료`)에만 남긴다.

### Today Plan 은 어디서 나오는가

이게 Career OS 의 핵심 로직이다.

```
                 TARGET CAREER
                       │
                       ▼
                JOB MARKET DATA
                       │
                       ▼
                  SKILL GAP
                       │
            ┌──────────┴──────────┐
            ▼                     ▼
       Learning 상태          Project 상태
            │                     │
            └──────────┬──────────┘
                       ▼
                   DEADLINES
           Jobs / Competitions / Applications
                       +
                 AVAILABLE TIME
          (캘린더 일정을 뺀 빈 시간, 하루 상한까지)
                       ↓
                PRIORITY ENGINE
                       ↓
                  TODAY PLAN
```

### Todo 앱과의 차이

```
Todo 앱      사용자가 해야 할 일을 넣는다
Career OS    시스템이 여러 정보를 보고 오늘 할 일을 결정한다
```

## 7. 추천 철학

Career OS 는 **할 일을 늘리는 서비스가 되어서는 안 된다.**

### 나쁜 예

```
AWS 도 공부하세요. Docker 도 공부하세요.
추천 도서 10권입니다. 공모전 20개를 찾았습니다.
```

이건 도움이 아니라 부담이다. 사용자는 이미 할 게 많다는 걸 안다.

### 좋은 예

```
지금 가장 가치가 높은 다음 행동은 이것입니다.

  AWS EC2 기초 — 30분

왜?
  저장된 공고 5건 중 4건이 AWS 를 요구하는데
  현재 AWS 증거가 없습니다.
```

### 추천이 갖춰야 할 4가지

| 원칙 | 의미 |
|---|---|
| **limited** | 개수를 제한한다. 3개를 넘기면 목록이지 추천이 아니다 |
| **prioritized** | 순서가 있다. 동등한 선택지를 나열하지 않는다 |
| **explainable** | 왜 지금 이것인지 설명할 수 있다 |
| **actionable** | 지금 바로 시작할 수 있는 크기다 |

### "하지 마세요" 도 추천이다

```
이 공모전은 지금 하지 마세요.

  마감까지 9일인데 필요 시간은 40시간입니다.
  진행 중인 AWS 프로젝트가 더 우선순위가 높습니다.
```

목록을 늘리는 것이 아니라 **줄이는 것**이 이 제품의 가치다.

## 8. 실행 우선 철학

큰 목표는 실행 가능한 작은 단위로 쪼개져야 한다.

```
❌ AWS 공부하기        무엇을 언제까지 어떻게? 시작할 수 없다

✅ 오늘 — 45분
   1. 보유 책 3장 읽기            15m
   2. EC2 인스턴스 직접 띄우기     20m
   3. 배운 내용 Agent 에게 설명    10m
```

완료하면 진행도가 쌓이고, 그 진행도가 다음 계획을 바꾼다.

## 9. 제품 경계 — 하지 않는 것

| 하지 않음 | 이유 |
|---|---|
| 경험을 지어내기 | AI 생성 자소서는 반드시 실제 Experience Bank 에 근거해야 한다 |
| 시장 통계를 임의 생성 | 수집된 실제 데이터에서만 계산한다 |
| 비교할 과거 없이 추세 그리기 | 스냅샷이 하나면 `unknown` 이라고 말한다 |
| 한 플랫폼에 종속 | 수집원은 어댑터로 분리한다 |
| 약관 위반 수집 | 각 소스의 허용 방식을 확인하고 연결한다. 공고는 사람이 읽고 붙여넣은 글을 규칙으로 읽는다 — 앱은 링크를 열지 않는다 |
| 자격 충족 여부 판정 | 공고마다 인정 기준이 다르다. 걸림돌 문장과 내 자격증 · 어학을 나란히 보여줄 뿐이다 |
| 한국어 맞춤법 검사기 자체 구현 | 외부 서비스로 위임한다 |
| 모든 데이터를 한눈에 보기(Overview)에 노출 | 한눈에 보기는 지금 상태의 요약이지 덤프가 아니다. 각 화면의 값을 모을 뿐 새로 판단하지 않는다 |
| 작업 화면까지 우주로 만들기 | 홈은 특별하게, 작업 화면은 편하게 (한국어 라벨) |
| 게임 같은 레벨업 연출 | 차분한 생산성 도구에서 멀어진다 |

## 10. v1 성공 조건

지금까지 나온 걸 전부 한 번에 만들려고 하면 또 길을 잃는다.
v1 은 **한 바퀴가 실제로 도는 것**으로 정의한다.

```
 1. 목표 직무와 공고를 본다
 2. Career OS 가 Skill Gap 을 계산한다
 3. 무엇을 먼저 공부할지 결정한다
 4. 내 책 / 저장 자료에서 지금 필요한 것을 선택한다
 5. Today Plan 을 만든다
 6. 학습하거나 프로젝트를 진행한다
 7. 완료 결과가 Progress / Evidence 로 남는다
 8. 프로젝트 결과를 Experience 로 저장한다
 9. 관심 공고에 내 Experience 를 연결한다
10. 지원 준비까지 이어간다
```

이 한 바퀴가 돌면 v1 성공이다.

**부분 기능이 아무리 많아도 이 바퀴가 안 돌면 실패다.**

## 11. 가장 중요한 규칙

Career OS 는 다음 두 문장 사이의 간격을 줄이기 위해 존재한다.

```
"나는 이런 커리어를 원한다"

          ↕

"그래서 오늘 정확히 무엇을 해야 하는지 안다"
```

모든 기술적·제품적 결정은 이 목표를 지지해야 한다.
